# BOSS 本机执行器

插件包包含 BOSS 执行器，使用本机已安装的 ego、Edge 或 Chrome。

1. 选 PDF 主简历，点「找岗位并准备投递」。插件提取方向、搜索 BOSS、读取当前页最多 5 个完整 JD，并准备最多 3 个岗位。方向不明确时才需要输入关键词。DOCX 和文本简历也能搜索，但要先保存 PDF 才能准备投递图片。
2. 第一次使用需在浏览器登录；遇到安全验证时，在浏览器处理后点「验证后继续」。
3. 在投递任务里点「查看简历」，直接核对实际要发出的各页图片。可以把不想投的岗位移出本批，确认后才会顺序投递。要先按 JD 改写简历，可返回结果，点「查看岗位」。

每个岗位拥有独立冻结记录：JD、简历版本、PDF 哈希及图片哈希共同绑定。插件以单岗位批次复用现有执行器，因此各岗位可以使用不同附件，不要求整批共用一份简历。预览有效期由执行器提供，过期后手动刷新核对。其他岗位派生简历不能用于当前 JD。

原 PDF 直接转图时保留其原排版及照片；插件重新生成的岗位版 PDF 仍为文本排版，转图不会恢复已丢失的布局。最多三页、单图 5 MB、合计 10 MB，超出时拒绝，不截断。图片保存在插件私有资料目录，只有确认后才由执行器上传到 BOSS。

发送确认只能从用户卡片操作，模型只有准备权限。重复点击、旧摘要、被篡改的图片及跨岗位版本会拒绝。请求前写入执行状态；连接断开、响应丢失或缺回执时标记待核对，不能再次确认。重新连接后按原批次编号读取结果，恢复界面不会恢复发送。

找岗位时会自动连接浏览器。重启 DSH 后，如果要继续核对已有任务，可以在任务页点「连接浏览器」。插件会记住上次使用的浏览器；专用 Edge 和 Chrome 保存各自的登录状态，只有会话失效才需要重新登录。ego 装在非默认位置时，可用 `EGO_BROWSER_EXECUTABLE` 指定可执行文件。

已有批次可通过 `boss_delivery_status` 查询并缓存回执、通过 `boss_pause_delivery` 请求暂停。恢复卡片只读本机缓存，不重新联系招聘方。结果不明时不要创建新批次重发，先在官网人工核对。

在 Windows 上，用独立浏览器资料实测了 Edge 和 Chrome。Edge 从 DSH 工作台启动并打开了 BOSS。Chrome 打开 BOSS 后经过验证页，随后到达登录页。登录后的岗位结果和真实投递未在这次测试中验证。自动测试另覆盖冻结附件、人工确认、批次状态和回执。

## 一次准备多个岗位

让助手先保存求职方向、城市和排除条件，然后按当前列表筛选：`boss_shortlist` 默认最多读取 5 个完整 JD，可设 1–10，且不超过目标数量限制。排除、未读取和失败均保留原因；工作地不明确时标记待核对，不把 JD 中提到的城市当成工作地。匹配证据来自简历原文，不能代替逐条 JD 分析，也没有凭空的匹配分数。目前不自动翻页。

自动准备生成的批次出现在「投递任务」列表。点「查看批次」核对和确认，确认只覆盖该批次的岗位与附件，最长 15 分钟。手动准备的岗位可单独确认。

暂时不处理的单条任务或批次可以点「归档」。在「已归档」仍可查看任务和附件，点「恢复」可移回当前列表。整批归档会收起该批次中的岗位。正在执行或等待回执的任务需要先等状态更新，归档任务恢复后仍需按原流程核对。

执行时仅刷新同一内容的短期核对票据，不改动 JD、简历和图片。每个岗位完成并取得匹配回执后才开始下一个。异常、超时、授权过期或暂停会停止后续任务。无需模型逐步控制发送队列，不产生额外模型调用。

暂停后「重新核对未执行的岗位」只包含完全未开始的项目，生成新的待确认批次。部分执行或结果不明的岗位不会混进去。宿主重启后批次显示暂停；重新连接并读取原批次回执，再决定下一步，不自动恢复执行。电脑须保持运行，当前没有后台常驻服务。

BOSS 记录保存在插件 SQLite，执行器回执保存在插件数据目录，出现在工作台「投递记录」及总览。核验状态对应官网消息及图片回执。其他项目已有的本地记录独立保存。
